# What is in `results/`

This directory holds a mix of frozen manuscript outputs, superseded earlier runs,
diagnostic probes and dead stubs from killed jobs. Nothing about a directory's
name tells you which it is, and mistaking a stub for a result has cost this
project real time. Every entry below is classified, and the classification is
based on the files' actual contents as of **2026-09-04**, not on memory.

**Four classes:**

| | meaning |
|---|---|
| **FROZEN** | backs the abstract, the poster or the paper. Do not regenerate, overwrite or "fix". |
| **SUPERSEDED** | a real, completed run that a later one replaced. Kept for the record. |
| **DIAGNOSTIC** | a probe. Answers a methods question; never quoted as a result. |
| **DEAD** | a partial stub from a killed or failed run. Carries no result. **Do not read as one.** |

## Rules

1. **Never overwrite a FROZEN directory.** The abstract and the paper quote it.
2. **Pick a fresh log name** rather than overwriting a previous run's record,
   including for failed runs — a failure is evidence about a bug.
3. **`tee | tail` reports the pipeline's exit status, not Python's.** A killed
   run once reported "exit code 0" because `tail` succeeded. Confirm a log ends
   with its expected final line before believing a run finished.
4. **Arrow prints four `sysctlbyname ... Operation not permitted` lines** at
   every `read_parquet` inside the agent sandbox. Harmless. Filter with
   `grep -v sysctlbyname`.
5. **`scorer_sensitivity_hpc4/` is still not quotable**, and the macOS arms have
   now landed, so the reason is sharper than it was: its own control arm failed
   on that machine while the identical script passed on macOS. That makes it
   evidence **about A9**, not about scorers. Quote `scorer_sensitivity_local/`.
6. **A `.npz` that is half of a two-machine experiment is not a result.**
   `bisect_macos.npz` is complete, correct, and answers nothing on its own.
   Do not write a conclusion from one half.
7. **DECIDED 2026-09-07 — the two `bisect_*.npz` files STAY, and the question is
   closed.** It had been carried unresolved through handoffs #29, #30, #31 and
   #32 as "2.18 MB each and git-tracked, decide whether they should stay now
   that they no longer carry the explanation". They do still carry something,
   and it is not sentimental: `19_check_numbers.py` **opens both files** (at the
   `bisect_macos.npz` / `bisect_hpc4.npz` reads) and turns them into three
   checked authorities — `bisect_macos_pooled`, `bisect_hpc4_pooled`, and
   `bisect_platform_delta`, which is DERIVED from the pair rather than typed, so
   it cannot drift from the two numbers it is the difference of. Deleting them
   would not merely free 4.37 MB; it would move three full-precision quotes in
   `14-SCIENCE-AUDIT.md` and in this file from **verified** to **exempted**,
   which is the exact downgrade the full-precision rule exists to prevent. The
   size argument was also never strong: 4.37 MB against a `predictions.csv.gz`
   of 14.9 MB already tracked in this directory. Re-open this only if those
   three authorities are removed from the checker first — and note that the
   files' **byte-for-byte identical size** (2,182,700 b each) is itself the
   cheapest structural check that the two halves match, so it is worth keeping
   as well.
